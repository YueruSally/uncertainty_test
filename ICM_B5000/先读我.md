# I、C、M 组件与联合训练

打开根目录的 **01_全部方法平均配对提升.csv** 即可查看指定的 11 行结果。三个百分比列的参照都是 Base，最后两项是 5,000 次评价时的运行时间和胜／平／负。CSV 按提供的原件逐字节保留，包括列标题和原有空列。

## 这张表对应的开发比较

S0–S8 各用 1 个开发实例，每个实例 3 个共同算法种子（993001、993002、993003），每种方法有 27 次运行。共 11 种方法。种群为 250，每实例固定 100 个优化情景，搜索预算上限为 5,000 次方案评价。在同一次搜索的 400、1,000、5,000 次评价处记录前沿。搜索由评价预算控制，代码未设定固定运行 200 代。

原统计程序在同一实例内汇总所有方法、种子和三个记录点的前沿，为三个目标分别取共同的最小值与最大值。参考点为 (1.1, 1.1, 1.1)。相对 Base 的提升在同一实例、同一种子、同一记录点配对计算，再汇总。开发统计导出的计时字段为 optimisation_seconds。

**结果来源。** 根目录的 CSV 是使用者指定的汇总表。归档的逐运行数据与该表在 C、M 的提升、部分胜平负和计时等处有差异。例如，指定表中 5,000 次评价的 C Transformer 为 +5.5%，归档的开发结果约为 −0.55%。这次整理没有重新计算或替换指定表中的数值。若从运行记录导出统计，请以导出目录中实际生成的数据为准。

## 从源码运行

源码附带运输网络工作簿、口岸事件、起讫地划分、实例生成模板、历史归一化输入和各阶段配置。归档模型权重没有收进本包；从头运行下列阶段会采集反馈、训练并生成权重。若只查看结果，直接打开 CSV 即可。

原环境为 Linux CPU，Python 3.10、PyTorch 1.12.1、NumPy 1.23.5。解压到有写权限的目录，在包根目录准备环境：

```bash
conda env create -f environment.yml
conda activate icm-components
```

按顺序逐阶段执行，确认该阶段正常完成后再执行下一行。默认两个工作进程，可用 MAX_WORKERS 调整。

```bash
bash run.sh collect
bash run.sh shared
bash run.sh independent
bash run.sh compare
bash run.sh ppo
bash run.sh confirm
bash run.sh export
```

collect 生成多配置实例并收集历史 B20000 反馈。shared 会审核旧数据并采集正式 B50000 监督反馈、拟合共享网络。independent 用相应的训练数据拟合独立网络。compare 执行 B5000 单组件和组合开发比较及原版 PPO。ppo 训练后续终局 PPO，confirm 在原开发面板比较固定 u1，export 按逐运行记录导出统计。正式监督训练与开发比较使用不同的评价预算。

运行输出位于 expanda/transformer_ppo_runs/diagnostics/。从头运行请使用新的解压目录，历史运行计划会校验代码、数据和路径。confirm 按历史比较协议校验选中的更新检查点，只有复现 u1 选择时才会执行这项固定模型比较。
